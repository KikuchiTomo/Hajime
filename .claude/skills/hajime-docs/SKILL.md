# ドキュメントの決まり

## どこに書くか

書く前に，その文書の目的を 1 つに決める．混ざっていたら分ける．

| 目的 | 置き場所 | 書き方 |
|---|---|---|
| 使う人が読む(インストール・使い方・設定) | `apps/docs-site/content/docs/` | https://haji.men/docs/ に載る．リポジトリにほかの写しを置かない |
| 作る人が構成と決まりを知る | `docs/dev/` | ARCHITECTURE・GUIDELINES などに追記 |
| 判断の理由を残す | `docs/dev/adr/` | `0000-template.md` に従う |
| 何を作るか決める | `docs/specs/` | 要件の ID(R-xx)と受け入れ条件 |

## サイトに載せるための決まり

- `apps/docs-site/content/` のページには frontmatter の `title` と `description` を書く
- ほかのページへのリンクは相対パス(`usage.md`)．Hextra が URL に直す
- 図は SVG かテキストの図．画像の中に文字を焼き込まない
- 英語は `<名前>.en.md`．日本語を先に書く
- 1 ページに見出しの 2 階層(`##` と `###`)まで．深くなったらページを分ける

## 文体

- 日本語の文章は `japanese-writing` スキル(利用者の環境に入っている)の決まりに従う．無い環境では次を守る
  - 句読点は「，」と「．」
  - README と使う人向けの文書は「です・ます」，`docs/dev/` とスキルとコードのコメントは「だ・である」か体言止め
  - 比喩・誇張(非常に，極めて)・記号の多用を避け，何がどうなるかを具体的に書く
- 言葉は，ふつうに通じるものを選ぶ．熟語を使うところを和語に言い換えない(「配る」ではなく「配布する」)．UI の部品の名前は，定着したカタカナの言葉をそのまま使う(タグ・ラベル・ボタン・チップ・バッジ・スイッチ・ツールチップ・ポップオーバー・パディング)．直訳した造語(札・地・縁 など)を作らない．背景・枠線・端のように，ふつうの言い方がある所はそれを使う
- 製品名は「Hajime IME」と書く．文書・画面の文言・インストーラー・PR の説明のどこでも，「はじめ」や「Hajime」だけでは呼ばない．バンドル ID・パス・リポジトリ名・型やモジュールの名前(`men.haji.inputmethod.Hajime`，`Hajime.app`，`KikuchiTomo/Hajime`，`HajimeCore`)は名前ではなく識別子なので変えない
- `CHANGELOG.md` の行は利用者が書く．エージェントは書き換えず，会話で更新内容を簡潔に伝えて頼む．書きぶりは次のとおりで，Discord の更新履歴を手本に遊んでよい．ほとんどの行は「〜できるようになりました」「〜の不具合を修正しました」の普通の文で書き，ネタのある項目にだけ短い一言を添える(全部の行にオチを付けない)．何が変わったかを最初の文で書き，冗談のために事実を曲げない．用語は画面の表記に合わせ，熟語を使うところを和語に言い換えない(「配る」ではなく「配布する」)．節の中は「追加」「変更」「修正」に分け，片方の OS だけの変更は行の頭に「macOS:」「Windows:」を付ける．句読点は「，」「．」で，行の終わりにも「．」を付ける(「！」や絵文字で終わる行は除く)．PR 番号は書かない(GitHub のリリースノートには，マージした PR の一覧が別に付く)．`CHANGELOG.md` は利用者が読むので，前書きに書き手への決まりや手順を書かない(決まりは CONTRIBUTING.md とこのスキルに置く)
- コードのコメントは「なぜそうするか」を書く．何をしているかはコードで読めるようにする
- 文書の中の値(色・寸法・既定値)は，置き場所のファイルを示して抜粋にとどめる．値を二重に持たないため

## 設計とあわせて更新する文書

| 変えたもの | 更新する文書 |
|---|---|
| ディレクトリ・層・モジュール | `docs/dev/ARCHITECTURE.md` と `hajime-architecture/scripts/check_layers.py` |
| 置き場所・名前・書き方の決まり | `docs/dev/GUIDELINES.md` |
| 保存先・通信・外から読むファイル | `docs/dev/SECURITY-MODEL.md` |
| 色・寸法・テーマ | `design/tokens/tokens.json` と `docs/dev/DESIGN-SYSTEM.md` |
| 利用者が触れる設定やキー | `apps/docs-site/content/docs/settings.md` |
| 判断そのもの | 新しい ADR |
