# Hajime のデザイン

決まりの本体は `docs/dev/DESIGN-SYSTEM.md`．値は `design/tokens/tokens.json` だけにある．

Web の画面(ドキュメントサイト・モックアップ)を作るときは，あわせて `frontend-design` スキルを読む．ただしブランドの方向(漢字Talk 7・シティポップの東京)はこのスキルで決まっているので，`frontend-design` の「方向を一から考える」部分は飛ばし，品質の基準と自己批評の手順を使う．

## 作業の順序

1. DESIGN-SYSTEM.md を読み，変える部品(候補ウィンドウ・種類の行・補正・モードの札・設定アプリ)を特定する
2. 新しい値が要るなら，先に `tokens.json` に足す．コードに色や寸法を直接書かない
3. `python3 -I tools/tokens/check_contrast.py` を通す．新しい色の組み合わせは `$extensions.hajime.contrast` に足してから検査する
4. 実装する．3 つのテーマ(glass・platinum・desk)と，ライト・ダーク・コントラストを上げる設定のすべてで見た目を確かめる
5. スクリーンショットか HTML のモックアップを `design/mockups/` に置き，PR に貼る

## 描画の決まり

- プラチナ外観の立体の縁は，画像ではなく線で描く．外枠 1 ドット，その内側に光の縁(左と上)と影の縁(右と下)を 1 ドットずつ
- 線はデバイスのピクセルにそろえる．macOS は `backingScaleFactor`，Windows は DPI から 1 ドットのデバイスピクセル数を求め，座標を整数に丸める．ぼけた 1 ドットの線は，このデザインでは不具合として扱う
- 既定のテーマ(標準)は，暗い地に青い選択と赤い補正，角丸，直線の枝，丸い書体．色は tokens.json の `theme.standard`，角の丸みは `size.standard-theme`．寸法は角丸のテーマと同じ `size.glass`
- platinum と desk は角を丸めない．影は desk だけ，ぼかしの無い 2 ドットの影を 1 段
- 動きは表のとおりで，候補の表示と選択の移動には付けない．「視差効果を減らす」が有効なら，フェードも止める

## 文字

- 文字は OS の書体だけを使う(同梱のフォントは無い)．テーマごとの系統は ResolvedTheme.Typeface(システム・明朝・等幅・丸ゴシック)
- キーは文字の記号(↓ ⇧ など)で書かず，SF Symbols のアイコンをキーキャップの札に入れて描く(GlassDrawing.drawHints)
- 選択肢やメニューの名前に括弧で説明を足さない．名前は短い名詞の形にする(「スペース幅」「日付と時刻に変換」)．説明が要るなら設定の画面の注記に書く
- 購入フォントは使わない(再配布できない)
- 半角カタカナの候補は，等幅にならないことを前提に幅を測って並べる

## よくある崩れ

- 標準のテーマなのに platinum や desk で表示される: テーマの値 `automatic` と古い `native` を標準のテーマに解決していない
- 種類の行がふだんから強調されている: 強調は上キーで移ったときだけ
- 補正の下線が通常の変換中の下線と同じ: 補正は `correction` 色の点線．変換中は文字色の実線
- 候補ウィンドウが画面の端で切れる: 位置は core の `WindowPositioning` で決め，アダプタで計算しない

## レビューの観点

- [ ] 値がすべてトークンから来ている(`grep` で `#[0-9A-Fa-f]{6}` や `NSColor(red:` を探す)
- [ ] コントラストの検査が通る
- [ ] 3 つのテーマ(glass・platinum・desk)，ライト・ダーク，コントラストを上げる設定で崩れない
- [ ] VoiceOver・ナレーターが候補と選択位置を読み上げる
- [ ] 1 ドットの線がぼけていない(2 倍に拡大したスクリーンショットで確かめる)
