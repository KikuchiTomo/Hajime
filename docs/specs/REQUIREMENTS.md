# 要件

Hajime IME が満たす要件の一覧です．機能の仕様書(`docs/specs/<id>-*.md`)はここにある ID を参照して書きます．
受け入れ条件は，テストか手動の確認手順に落とせる粒度で書きます．

対象は macOS と Windows です．Linux などは後で足す前提で，プラットフォームに依存しない部分を `core/` に寄せます(`docs/dev/ARCHITECTURE.md`)．

## R-01 ライブ変換

打っている途中の読みを，確定キーを押さなくても漢字かな混じりで表示する．

- 受け入れ条件
  - ローマ字・かな入力のどちらでも動く
  - 1 キーの処理(ライブ変換を含む)は，p95 で 50ms 以内．打鍵の間隔(速い人で 170ms 前後)より十分に短くする
    - 2026-10-26 の計測(Apple Silicon，Release，30 字ほどの文．`core/Tests/HajimeEngineTests/LatencyProbeTests.swift`): Zenzai なしで p50 18ms，p95 30ms．Zenzai ありで p50 20ms，p95 34ms
    - 2026-10-26 の再計測(72 キー，nn を含む文．絵文字の辞書を変換のたびに作らないようにしたあと): Zenzai ありで p50 0.8ms，p95 14ms．評価用の文の 1 回の変換は中央値 16ms(前は 37ms)
    - Zenzai のような重い変換を入れて間に合わなくなったら，読みのまま表示して結果が出たら置き換える形にする
  - 句読点・Enter・Space で，表示中の結果を確定または候補選択に移れる
  - 設定の「？と！で確定」をオンにすると，？ と ！ を打ったときもその記号まで確定する(既定はオフ)
  - アプリごとの設定(R-06)でライブ変換を切れる
- 打っている途中の見せ方(`LiveConversionRule`)
  - 打鍵が続くあいだは，3 文字に満たない読みと，読みが 3 文字以下の末尾の語をかなのまま見せる(「らい」を「雷」にしない)
  - 打鍵が 0.4 秒止まったとき，Space・Enter のときは，変換した文をそのまま見せる．Enter は変換した文を確定する
  - 評価用の文(`core/Evaluation/conversion-basic.tsv`，Zenzai あり)で，確定する文と食い違う漢字やカタカナを見せた途中表示は 240 時点中 50 から 23 に減った(`hajime-playground --evaluate-live`)

## R-02 タイプミスの自動補正

日本語と英語のタイプミスを，打っているあいだに補正する．補正はいつでも元に戻せる．

- 補正の種類
  - かなに化けた英単語: `pyてょn` → `python`(ローマ字入力のまま英単語を打ってしまった場合)
  - 英単語の綴り: `pthon` → `python`
  - 日本語のローマ字の打ち間違い: `konnnitiha` の `nnn` のような重複，隣のキーの押し間違い，母音の打ち間違い(`kyounotenkihayoudesune` → 今日の天気は良いですね)
- 日本語の打ち間違いの直し方
  - ライブ変換で打鍵が `DefaultSettings.liveCorrectionDelay`(0.8 秒)止まったときと，Space で変換を始めるときに，Zenzai で打ったキー全体を見直す．打鍵ごとには見直さない(1 文 0.1〜0.7 秒かかるため)
  - 打ち間違いの種類: 近くのキーの押し間違い，余分なキー，2 つのキーの入れ替わり(azooKey の訂正)に加え，Hajime IME の azooKey のフォークで，ローマ字の母音の取り違え(`onagai` → お願い)，同じキーの重なり(`koonnnitiha`)，余分な母音(`tututa` → 釣った)，打ち忘れ(母音と，同じキーの 2 回目．`haitenki` → いい天気)を扱う．文の末尾の重なりはフォークの訂正が扱わないので，重なりを 1 回にした並びも見直して比べる(手間 `DefaultSettings.repeatedKeyCost`)
  - 誤りの種類を決め打ちしない訂正(`KeyEditSearch`): 打ったキーの 1 か所を，どのキーとの取り違え・打ち忘れ・余分な 1 打・隣どうしの入れ替えに変えた並びを全部作る．変わったところの前後の変換のもっともらしさで上位 `DefaultSettings.keyEditCandidateCount` 件に絞り，Zenzai で採点して上の訂正の候補と合わせる．音の変わらない書き誤り(ず/づ・じ/ぢ・わ/は・え/へ・お/を・おう/おお)は聞いたとおりに書いた誤りとして手間を小さくする(`見ずらい` → 見づらい，`いいずらい` → 言いづらい，`とうり` → 通り)．前に見直した部分は探し直さない
  - 直すかどうかは，言語モデルの点数・読みを変換したときのもっともらしさの差・手間を合わせた点数(`ReadingCorrection.rank`．重みは `DefaultSettings.correctionPlausibilityWeight`・`correctionCostWeight`)で比べる．言語モデルはかなの並びを見るので書き分けの誤りを見分けにくく，変換のもっともらしさで補う．重みと境目は評価の文で，正しい文を誤って直さない範囲で直せる文が最も多くなるように決めた
  - 直した読みが打ったままの読みより十分にもっともらしいとき(点数の差が `DefaultSettings.readingCorrectionMargin` 以上)は直して見せる．差がそれより小さく `DefaultSettings.readingSuggestionMargin` 以上なら直さず「もしかして」と示し，Tab で直せるようにする(打ち間違いと決めつけない)
  - 直したときは点線の下線と，入力位置の下の案内で知らせ，Esc で打ったままの読みに戻す．戻したキーのあいだは直し直さない
  - 直したあとも，打ったままの読みの変換候補を選べるようにする(直すかどうかは利用者が選ぶ)．分岐図・一覧・入力中の候補で，打ったままの読みの候補の上位 `DefaultSettings.typedAlternativeCount` 個を直した第 1 候補のすぐ後ろに，残りを末尾に並べ，「入力のまま」と添える．分岐図では，直した部分を打ったままの読みの語の区切りまで広げて 1 つの文節にする(「ubuntu」を「うぶんと」に直しても，「うぶんつ」全体の Ubuntu を選べる)
  - 訂正は探す幅 16 で求める．1 文に 0.2〜2.8 秒(中央値 1.1 秒，Release，Apple M1 Pro)かかるので，表示に使う変換器とは別の変換器でメインスレッドの外で求め(`ZenzaiTypoService`)，求め終わったときに打ったキーが変わっていなければ見直す．Space で変換するときに求め終わっていなければ，待たずに直さず変換する
  - `core/Evaluation/typo-correction.tsv` で測る(`hajime-playground --evaluate-typo`)．2026-10-26 の結果: 打ち間違いの無い 20 文で誤って直した・示したのは 0，打ち間違いのある 16 文で正しく直したのは 14(探す幅 4 では 10，8 では 11)．書き誤り・キーの打ち間違いの文を足した 83 文(正しい 45・打ち間違い 38)では，`KeyEditSearch` を入れる前は誤って直した 1・違う文に直した・示した 7・正しく直した 20・示した 3，入れたあとは誤って直した 0・違う文に直した・示した 2・正しく直した 22・示した 3
- 英語の混ざる読み
  - 打ったとおりの英単語(「python」)と Shift で打った英字(「IME」)は，日本語の打ち間違いの見直しに含めない．見直すのは最後の英単語より後ろの日本語だけ(`Composition.boundaryAfterEnglish`)．英単語の綴りは英単語の補正(`EnglishWordCorrector`)の受け持ち．綴りを直した英単語(「sride」→「bride」)は日本語の打ち間違いを取り違えたことがあるので，見直しで読み直せるようにしておく
  - ローマ字として読めてしまう英単語(「gitwotukau」の「git」)は，英単語の終わりがローマ字の綴りの途中にかかり，後ろが助詞や「する」「です」で始まり，後ろだけを日本語として読んだもっともらしさから `DefaultSettings.wordReadAsRomajiCost` を引いても全体を日本語として読むより高いときに英単語にする(`TypoCorrectionRule.readsAsEnglish`)．「kitto」(きっと)・「kite」(来て)は日本語のまま．辞書を引く回数を抑えるため，ローマ字として読める部分は打鍵が止まったときと変換・確定の前にだけ調べ，読めない並びを含む部分(「react」+「wo」)は打鍵ごとに調べる
  - 分岐図では英数字の続く並びを 1 つの文節にする(`ClauseSplitter`．エンジンは英字を 1 文字ずつの語にする)．「pythonが｜すごい」「この｜IMEは」「AAAまで」
  - 評価の文に英語の混ざる文 9 文と，その打ち間違い 2 文を足した．2026-10-26 の結果: 英語の混ざる 9 文はすべて直さずに英単語のまま見せた(前は「pythongasugoi」を「ぴょんがすごい」，「gitwotukau」を「必要」に直していた)．打ち間違いの 2 文は 1 文を直し，1 文は直せなかった．もとの 83 文の結果は変わらない(誤って直した 0・正しく直した 22・示した 3)
- 受け入れ条件
  - 補正したことが見た目でわかる(`docs/dev/DESIGN-SYSTEM.md` の補正の表示)
  - 英単語の補正の直後に Space を押すと，打ったままの文字列に戻る．一覧の表示では打ったままの文字列を 2 番目に出す
  - 補正の辞書と判定は端末の中だけで行う．入力した文字列を外部に送らない(`docs/dev/SECURITY-MODEL.md`)
  - 補正の強さ(オフ・英単語のみ・英単語と日本語)を設定できる

  - 補正は種類ごとに切れる(英単語・日本語の打ち間違い・同じキーの重なり)．直さない語句と，打った英字を決まった語句にする置き換えの決まりを設定で足せる
  - よくある読み違い(「ふいんき」→ 雰囲気)は直さず，正しい語を候補に足して「もしかして」で示す．Tab で正しい読みにする

## R-03 変換候補の上の「種類」の行

変換中，候補一覧の上(分岐図では上の枝)に文字の種類の行を出し，上キーで移れる．設定の「候補の上に文字種の行を表示」で出さないようにできる．

- 種類: そのまま(ひらがな)・カタカナ・半角カタカナ・全角英数・半角英数
- 受け入れ条件
  - 候補一覧の先頭で上キーを押すと種類の行に移り，左右で選び，下キーで候補一覧に戻る
  - 種類の行の項目にもショートカット(例: 既定は macOS と同じ Control+K でカタカナ)を割り当てられる
  - 種類の行を出さない設定がある
  - 英数(全角英数・半角英数)に変えるキーを続けて押すと，英字を 入力どおり → 大文字 → 小文字 → 先頭だけ大文字 の順に変える．見た目の同じものは飛ばす(設定で切れる．既定はオン)

## R-04 ¥ と \ の扱い

JIS キーボードの ¥ キーで何を入れるかを，設定ひとつで変えられる．

- 受け入れ条件
  - 既定はバックスラッシュ(`\`)．プログラミングで困らないことを優先する
  - 「常に ¥」「常に \」「プログラミング用のアプリだけ \」を選べる
  - Option+¥ で逆の文字を入れられる
  - 全角の ¥ と半角の ¥ を取り違えない

## R-05 入力方式

- ローマ字入力
- かな入力(JIS かな配列)
- 英語のまま入力(以下 EN 入力．画面では英字入力)．英語配列のまま打ち，読みとして解釈できる並びには日本語の候補を出す
  - 例: `konnnitiha` と打つと，候補に「こんにちは」を出す
  - ライブ変換をする・しないを選べる(設定 `englishInputLiveConversion`．既定はしない)．しないときは，打った英字をそのまま見せ，日本語の候補を 1 つだけ添えて Tab で選ぶ．英字を勝手に日本語に置き換えると英語を打つ人の流れを止めるため，既定はしない
  - ライブ変換をするときは，ローマ字として読め，英語の辞書にない語を日本語にして見せる(`WordLanguageJudge` の `dictionaryOnly`)．英字は候補に添え，Esc で英字に戻す
- 英字入力(自動)．英語で打ちながら，日本語にできる語は語ごとに見分けて日本語にする(`kyouhaiitenki` は日本語，`hello world` は英語のまま)
  - 見分け方(`WordLanguageJudge` の `englishFirst`): 利用者の「いつも英語」「いつも日本語」の語と見分け方の決まり → ローマ字として読めなければ英語 → 英語の辞書にない語は，読みを変換したもっともらしさ(1 文字あたり `DefaultSettings.minimumJapanesePlausibilityPerCharacter` 以上)なら日本語 → 英語にも日本語にも読める語(`make`・`shine`)は前の語で見分ける(前が英語なら英語，日本語なら日本語．前は入力位置の前の文字列，読めないアプリでは前に確定した語) → 手がかりが無ければ英語
  - Zenzai の点数(`languageModelScores`)は使わない．1 語ごとに打鍵のたびに見分けるので，Zenzai を回すと 1 キーの処理が間に合わない(R-01)．軽い変換のもっともらしさ(`plausibility`)だけを使う
  - 打鍵ごとに見分ける(語は 4 文字から．短い語に日本語を出さない)．日本語にして見せている語は Space と Enter で日本語を確定し(空白や改行は入れない)，Esc で英字に戻す．英字を見せている語は英語の入力と同じに動く．Tab で分岐図を開いて変換を選べる
  - 評価(`core/Evaluation/english-auto.tsv`，`hajime-playground --evaluate-language`): 2026-10-26 の結果は 20 文中 19 文．誤った 1 文は「i love sushi」の sushi を日本語にした(評価で使う英語の辞書 `/usr/share/dict/words` に sushi が無いため．macOS のスペルチェッカーでは英語の辞書にある)
- 英語にも日本語にも読める語の扱いは，ローマ字入力でも使う(R-02)．ローマ字入力では前が英語のときと，利用者が英語にすると決めた語だけを英語にする(`japaneseFirst`)
  - 英語にした語も，変換の一覧と分岐図の下の枝に，打ったキーをローマ字として読んだ日本語の候補を並べる(「Let's 」のあとの `demo` でも「でも」「手も」を選べる)．分岐図ではかなの字種を上の枝に出す
- 不適切な語(「しね」→「死ね」)は，第 1 候補に出さない(`SupplementedConverter`．設定で切れる)．英字入力(自動)では前が日本語でなければ日本語にしない
- 受け入れ条件
  - 方式の切り替えは，設定の画面・ショートカット(Option+かな．ローマ字 → かな → 英字 → 英字(自動)の順)・キー設定の表の方式ごとのコマンドのどれでもできる．入力メニューには置かない(メニューは「ライブ変換」と「設定を開く…」だけにするよう指示を受けた．2026-10-26)
  - EN 入力でライブ変換しないとき，日本語の候補を出しても，Space や Enter の既定の動きは英語入力と同じ(候補は Tab などの明示した操作で選ぶ)
  - 英語か日本語かを決める語と決まりを設定の画面(英語と日本語)で足せる．打った文を試して結果を見られる

## R-06 プログラミング中に邪魔をしない

- アプリ(バンドル ID・実行ファイル名)ごとにプロファイルを割り当てる．エディタ・IDE・ターミナルには既定のプロファイルを用意する
- プログラミング用のプロファイル(エディタ・ターミナル)の既定
  - 記号は半角(`()[]{}<>;:'"` など)
  - 英単語の綴りの補正(R-02)は日本語の文中にあるときだけ行う．読みの中か，打ち始める前の入力位置の直前にかな・漢字があれば日本語の文中とみなす
  - 識別子らしい並び(`camelCase`，`snake_case`，`a.b`)は補正しない．英単語に続けて大文字・数字・`_`(エディタでは `.` も)を打ったら，直した英単語を打ったとおりに戻して続ける．`_`・`.`・英数字のすぐあとから打った英字は直さない(この 2 つはどのアプリでも)
  - ライブ変換は控えめ．打鍵が止まるまで読みのまま見せ，読みの末尾が英数字のあいだ(識別子を打っている途中)は止まっても変換せず，Enter でも読みのまま確定する．除外設定の「エディタとターミナルでライブ変換を控える」で切れる
- 受け入れ条件
  - Vim のノーマルモードに戻る Escape で，入力方式を英数に戻す設定がある
  - 変換中でないときに，IME がキーを横取りしない

## R-07 コマンド入力

ターミナルやコマンドパレットでコマンドを打つときに，日本語入力のままでも困らないようにする．

- 実装(`CommandLineState`)
  - ターミナルでも日本語の文を打つ(対話型のツールへの指示など)ので，行の頭から英字を流すことはしない
  - 行の頭でよく使うコマンドの名前(`git`，`ls`，`make` など約 120 個)を打って Space を押すと，打ったとおりの英字で確定し，その行の残りは英字と記号をそのまま流す
  - その行の引用符の中と `#` の後ろでは日本語を打てる．閉じる引用符で日本語を確定する
  - Enter・Ctrl+C・Ctrl+U・Cmd+Backspace・履歴の呼び出し(↑↓)・英数への切り替えで行が終わる．Backspace で行の頭まで消しても行の頭に戻る
  - 入力欄を離れたとき・貼り付けたとき・Option+文字を押したときは，行の中身が分からなくなるので「文の行」(コマンドの名前を見分けず，英字も流さない)として続ける．ただし何も入れていない行の頭なら行の頭のまま．分からないときは，ふつうに日本語を打てるほうへ倒す
  - # は語の頭(直前が空白)にあるときだけコメントとみなす．行の頭の # もコメント
  - 行の頭の空白・`(`・`{`・`\`(¥ キーを含む)・`!`・`$` のあとのコマンドの名前も見分ける(`(cd …`，`\git …`，`!git status`)．それ以外の記号(`@`・`*`・引用符・`` ` `` など)や英数で打った英字のあとは，日本語の文の行として扱う(`@claude これ見て`，`` `git rebase` のやり方 ``)
  - Tab の補完で入った文字は中身が分からないので，文の行として扱う．ただし何も入れていない行の頭の Tab と，Shift+Tab は補完ではないので扱いを変えない
- 受け入れ条件
  - ターミナルのプロファイルでは，行の頭でコマンドの名前を打って Space を押したら，その行の英数字と記号を確定済みの英字として流す
  - 行の頭から日本語の文を打つ場合(対話型のツールへの指示など)は，ふつうに日本語を打てる
  - 引用符の中など，日本語が来そうな位置では日本語の候補を出す
  - コマンドパレット(VS Code など)を開いたときの入力欄も対象にできる

## R-08 テンキー

- テンキーで打った数字と記号は，日本語のモードでも組み立て中の文字を確定してから半角で確定する(設定で切れる．既定はオン)
- 受け入れ条件: 読みを組み立てている途中でテンキーの 1 を押すと，読みを確定してから「1」を確定する
- 設定の「テンキーの Enter で計算」をオンにすると，テンキーの数字と記号を半角のまま読みに入れ，テンキーの Enter で式(「12*3」)に「=」を足して変換し，計算の結果(R-11)を第 1 候補にする．式でなければふつうの Enter(既定はオフ)

## R-09 日本語と英数を切り替えるキー

- 英数・かな・半角/全角・変換・無変換のキーと，好きなキーの組み合わせに，日本語入力・英数入力・切り替え を割り当てられる(キー設定の表．R-17)．割り当ては core に置き，macOS 版と Windows 版で同じ設定を使う
- 既定: 英数=英数，かな=日本語，半角/全角=切り替え，変換・無変換は切り替えに使わない(組み立て中の変換キーは変換，無変換キーはカタカナ)
- 受け入れ条件: 半角/全角を押すたびに日本語と英数が入れ替わる．変換を「日本語」にすると，英数のときに押して日本語になる

## R-10 記号の決まり

- 連続入力によるサジェスト(「->」→「→」)と，読み仮名入力によるサジェストの決まりを，設定の画面で書き換え・無効化・追加・既定に戻すができる
- 既定の決まりは変えず，利用者が変えた分だけを設定に重ねる．バージョンが上がって既定の決まりが増えても，利用者の変更は残る
- 受け入れ条件: 「->」を「⟶」に書き換えると，「->」と打ったときに「⟶」になる

## R-11 計算

- 「1+2*3=」のように = で終わる式を打つと，結果と式を候補の先頭に出す．式は自前の読み取りで計算し，文字列をプログラムとして実行しない
- 受け入れ条件: 「1+2*3=」の候補の先頭が「7」と「1+2*3=7」．0 で割る式や式でないものには出さない

## R-12 送り仮名

- 送り仮名の本則(行う)と許容(行なう)のどちらを先に出すかを選べる(既定は本則)．熟語の一部(「代表し」)と「行った(いった)」は書き換えない
- 受け入れ条件: 本則を選ぶと「おこなう」の第 1 候補が「行う」，許容を選ぶと「行なう」

## R-13 郵便番号変換

- 読みが郵便番号(「100-0001」「1000001」．全角の数字も)のとき，住所を候補に出す(既定はオン)．区切りがあれば先頭に，無ければ 2 番目に置く
- 事業所の個別の郵便番号では，事業所の住所(番地まで)・住所と事業所名・事業所名を候補に出す
- 郵便番号の表はアプリに同梱し，利用者の Mac では通信しない(docs/dev/POSTAL-CODES.md)
- 受け入れ条件: 「100-0001」の第 1 候補が「東京都千代田区千代田」．事業所の郵便番号では，住所と事業所名の候補が出る

## R-14 手書き入力

- 読めない漢字を手書きで探す(既定はオフ)．「手書き入力」のキー(既定は ⌃⌥H)で窓を出し，書いた線を端末の中の文字認識(macOS は Vision，Windows は Windows の手書き認識)で読んで候補を並べる．選ぶと入力先に入れる
- 受け入れ条件: 書いた文字が候補に出る．認識は通信しない

## R-15 設定とユーザー辞書の同期

- 利用者が選んだフォルダ(Dropbox・Google Drive・iCloud Drive など)に置いたファイルを介して，設定とユーザー辞書を Mac のあいだで同期する．アプリは通信しない．置き場所は差し替えられる形(`SyncBackend`)にし，将来ほかの置き場所を足せるようにする
- まとまりごとに「同期する」「この Mac だけ」を選べ，同期するまとまりの中でも項目ごとに「この Mac だけ」にできる．両方で変えたまとまりはあとで変えた方，ユーザー辞書は語の和集合と削除の墓標で合わせる
- 設定のファイルには形式のバージョンを書き，古いバージョンは読むときに移し替える．知らない項目は消さずに書き戻す
- 受け入れ条件: 2 台で同じフォルダを使うと，片方で変えた「同期する」まとまりの設定と登録した語がもう片方に届き，片方で消した語はもう片方でも消える．「この Mac だけ」のまとまりは届かない．バージョンを書いていない古い設定のファイルを読める．新しいバージョンの知らない項目は保存しても残る

## R-16 辞書の取り込み

- 数十万語の辞書のファイル(タブ区切り，SKK，macOS のユーザ辞書の plist．UTF-8，UTF-16，Shift_JIS，EUC-JP)を取り込める．辞書ごとにオン・オフ，名前，分野，優先度(一覧の順)を決める
- 辞書ごとに使う場面を選べる: 常に，選んだアプリだけ，文脈に合わせる(その辞書の語を最近確定するほど優先度を上げる)
- 取り込んだ語は起動時に読まない．辞書ごとの索引のファイルを読みで引く
- 分岐図で，選んでいる候補がどの辞書の語かを出す
- 取り込んだ辞書は，設定の同期(R-15)のフォルダで索引のファイルごとほかの Mac に運ぶ．中身の SHA-256 をバージョンとして設定に書き，運んだファイルはバージョンと合うときだけ使う
- 受け入れ条件: 30 万語の辞書を取り込んでも，1 つの読みを引くのに 1 ミリ秒かからない．「選んだアプリ」の辞書は，ほかのアプリでは候補に出ない．片方の Mac で取り込んだ辞書の語が，同期したもう片方の Mac でも引ける．書き換えられた索引は使わない

## R-17 キー設定の表

- すべてのキー操作を「状態・キー・コマンド」の行の表で決める．行は好きなだけ足せる．状態は いつでも・入力文字なし・入力中・変換中・英数．キーは修飾キー(⌃⌥⇧⌘)の任意の組み合わせと，文字・Space・Enter・Tab・Backspace・Delete・Esc・矢印・Home・End・PageUp・PageDown・F1〜F20・英数・かな・半角/全角・変換・無変換
- コマンドは，入力モード(日本語入力・英数入力・切り替え・入力方式の切り替え・ローマ字入力・かな入力・英字入力・英字入力(自動))，空白(設定の幅・逆の幅・半角・全角)，変換・学習を使わずに変換・削除・区切り・「もしかして」，字種(全文をひらがな・全角カタカナ・半角カタカナ・全角英数・半角英数に，かなの種類の切り替え，選んでいる文節だけをひらがな・全角カタカナ・半角カタカナに)，候補(前後・ページ・先頭・末尾)，文節(前後・先頭・末尾・誤りやすい文節・長さ・区切り)，確定・先頭の文節だけ確定・取り消し・全文を読みに戻す・読みに戻して末尾から編集・直前の変更の取り消し・予測の確定の取り消し・取り消して英数に，学習(候補を学習から削除・最後の学習を取り消し・予測に表示しない)，設定を開く・ライブ変換・手書き
- 同じ状態の同じキーは下の行を使い，状態を選んだ行は いつでも の行より優先する．設定の画面で，使われない行・文字を打てなくなる行・確定や取り消しのキーが無い状態を知らせる
- 全文を読みに戻すと，読みを変えるまではライブ変換がオンでも読みのまま見せ，読みのまま確定する．読みに戻して末尾から編集するときは，打っている途中と同じに見せる
- 直前の変更の取り消しは，変換中に変えた候補の選択(表記)と文節の区切りを 1 段ずつ戻し，戻すものが無ければ全文を読みに戻す．段は 8 段まで．続けて同じ種類の変更をしたとき(候補を続けて送る，同じ字種のキーを続けて押す，文節の長さを続けて変える)は 1 段にまとめる
- ひな形(標準・Windows 風・Mac 風・ATOK 風・Emacs 風・Vim 風)を読み込める．以前のバージョンの変換中のキーと切り替えのキーの設定は表に移し替える
- 候補ウィンドウの足元の案内(分岐図・一覧・入力中の候補の窓)と，打ち間違いの案内に出すキーは表から引く．案内はキーキャップの札で描き，複数のキーはキーごとに札を分ける．設定の「キーの案内を表示」をオフにすると足元の案内を出さない
- 受け入れ条件: 変換中に ⌃7 を「全角カタカナに変換」に割り当てると，変換中に ⌃7 でカタカナになる．標準の表では，変換中の F7 で選んでいる文節だけがカタカナになり，候補を変えたあとの Esc で変える前の候補に戻り，もう一度の Esc で読みに戻る．入力文字なしで ⇧Space は全角空白(スペース幅が半角のとき)．以前のバージョンで既定のまま保存した設定は標準の表として読める

## R-18 連想変換

- 変換中の語と似た意味の語・関わりのある語を，通常の候補と混ぜずに別の一覧に切り替えて出す．一覧は元の語を見出しにし，意味(語義)のまとまりごとに分ける．まとまりには意味の説明を添える
- 入力中は「連想変換」のキー(標準は Shift+Space)で変換してから，変換中は Shift+↑ で，選んでいる文節を連想の一覧にする．キーはキー設定の表(R-17)で変えられる
- 一覧は候補の出し方の設定に従い，分岐図なら注目している文節の下の枝に，一覧なら候補の一覧に出す．上下で語を，左右で意味のまとまりを移る．Enter で確定し，Esc か同じキーで元の変換に戻る．ほかのキーは選んだ語を文節に入れてから行う．連想の語は学習しない
- 連想の語は取り込んだ連想の辞書(差し替えられる形．`AssociationLookup`)から引く．第三者の辞書は同梱しない．辞書ごとにオン・オフと優先度(一覧の順)を決める．選んでいる語で見つからなければ読みでも引く
- 設定: 連想変換のオン・オフ，一覧に出す語の数，連想があることを候補の窓の足元に知らせるか．オフのとき，入力中の連想変換のキーはふつうの変換になる
- 受け入れ条件: 入力中の Shift+Space で連想の一覧で変換に入り，変換中の Shift+Space は前の候補のまま．Esc で元の変換に戻る．辞書に無い語では変換のまま「連想はありません」と知らせる．以前のバージョンで標準のキー設定のまま保存した設定でも，入力中の Shift+Space と変換中の Shift+↑ で連想変換になる(Ctrl+Tab はアプリのタブの切り替えとぶつかるので使わない)

## R-19 更新の確認

- 設定の画面の「情報」(Hajime IME のアイコン・名前・バージョンの横)と，macOS の入力メニューに「更新を確認」を置く．Windows は設定の画面の「情報」に置く
- 押したときだけ https://haji.men/download/latest.json(`DefaultSettings.updateManifestURL`)を取り，今のバージョンより新しければ，飛ばしたバージョンも含めた変更点(CHANGELOG.md の節)を見せて更新するかを聞く．新しくなければ最新であることを知らせる
- 「更新する」を選ぶと，配布物を https://haji.men/download/ の下からだけ取り，latest.json の SHA-256 と合うかを確かめてから入れる．大きさと待ち時間に上限を設ける(`DefaultSettings` の update で始まる値)
  - macOS: IME の本体はサンドボックスの中で通信の権限を持たないまま，Contents/Helpers の更新用のアプリ(Hajime IME Updater)が通信とインストールを行う．.pkg が Apple の公証を通り，本体と同じチームの Developer ID で署名されているかを `spctl` で確かめ，管理者のパスワードを聞いて OS のインストーラーで入れる．入れたあとはログアウトを求めず，postinstall が古い本体を止めて次の入力から新しいバージョンで動く
  - Windows: 設定の画面のアプリが通信し，`msiexec` で .msi を入れる．TSF の DLL をバージョンごとのフォルダに置き，上書きのときは再起動を求めない
- 送るのは GET の要求(User-Agent に名前とバージョンと OS)だけで，入力の中身・設定・識別子は送らない．自動では確かめない
- 確かめられないとき(通信の失敗，形の違う知らせ，ハッシュや署名の不一致，署名の無い開発版)は入れずに理由を出し，最新のリリースのページ(`DefaultSettings.latestReleaseURL`)を開けるようにする
- 受け入れ条件: 古いバージョンで「更新を確認」を押すと変更点と「更新する」が出て，選ぶとログアウトや再起動なしに新しいバージョンで入力できる．最新のバージョンで押すと最新であると出る．押すまでアプリから何も送らない

## R-20 うろ覚えの語と発音どおりの綴り

- うろ覚えで読みを少し違えて打った外来語(「しゅみれーしょん」→ シミュレーション，「こみにけーしょん」→ コミュニケーション，「ぶるどっく」→ ブルドッグ)を，変換の一覧と分岐図の候補に出す．読みを 1 か所だけ組み替え(小さい「ゃゅょ」の位置・抜け，濁点・半濁点，長音．`LooseReadings`)，辞書の 1 語になるものを使う．打っているあいだ(ライブ変換)には求めない
- 発音どおりに綴った英単語(「ふぉと」→ photo)を候補に出す．読みをローマ字にした綴りに，音の同じ綴りの置き換え(f/ph，k/c など．`PhoneticSpelling`)を 2 か所まで当て，英単語の辞書にあるものを使う
- 手の置き場所が横に 1 キーずれたまま打った並び(両手・左手だけ・右手だけ，左右)を戻した並びも，打ち間違いの見直し(R-02)で比べる．キーの位置は設定のキー配列(QWERTY・Dvorak・Colemak)から引く(`HandShift`)．打ったキーがローマ字として読み切れるときは試さない(試験的)
- どれも既定ではオフ．第 1 候補は変えない
- 受け入れ条件: オンにすると「しゅみれーしょん」の一覧に「シミュレーション」が出る．QWERTY で右手だけ右にずらして打った「lpmmmotoja」を「こんにちは」に直せる

## R-21 ユーザー辞書の読みと動的な語

- ユーザー辞書の読みはひらがなのほか，ローマ字・英字でも登録できる(「gh」→ GitHub，「toyota」→ トヨタ)．ローマ字の読みは打ったときと同じ決まりでかなにして引く(`ReadingNormalization`)．かなにならない読みは読み全体が一致したときだけ出す
- 他の IME の書き出し(Google 日本語入力・Microsoft IME の UTF-16・ATOK・macOS のユーザ辞書の plist・SKK)を，ユーザー辞書にも辞書の取り込み(R-16)にもそのまま読み込める．英字の読みも読む
- 動的な語: 設定でオンにすると，単語に書いた `{datetime:YYYY/MM/DD hh:mm:ss}`・`{date}`・`{time}`・`{utc}`・`{unixtime}`・`{holiday}`・`{season}`・`{greeting}`・`{days:M/D}`・`{age:Y-M-D}`・`{uuid}`・`{random:a-b}`・`{alnum:n}`・`{hex:n}`・`{pick:A,B}` と，`{名前|upper}` などの変換(`TextFilter`．大文字・かなの種類・幅・ヘボン式のローマ字・snake_case などの書き方・URL の形・文字数・漢数字・大字・3 桁区切り・丸数字・HTML・Base64)を入れるときの値にする(`TextTemplate`)．日時は営業日(土日と祝日を除く日．祝日は `JapaneseCalendar`)でもずらせ，書式に年度・和風月名・干支を書ける．クリップボードや画面の中身を読む名前，プログラムを動かす名前は作らない
- 日時は分・時間・日・週・月・年でずらし(`{time+30m}`・`{date+1M}`)，その週(月曜から日曜)の曜日・その月の日・月末に合わせられる(`{date+1w@mon}`・`{date@end}`)．暦の計算は先発グレゴリオ暦で core が行い，OS の暦に頼らない(`CalendarArithmetic`)．元号は始まりの日で切り替える
- 「にちじ」で日付と時刻を合わせた形(`YYYY/MM/DD hh:mm:ss`・ISO 8601 など 8 通り)を出す
- 受け入れ条件: 「gh」を登録して gh を変換すると GitHub が出る．「{datetime:YYYY}年」を登録すると今年が出る．「{date+1M@1:M/D}」を登録すると来月 1 日が出る

## R-22 コマンド(ランチャー)と変換マクロ

- 読みで呼び出すコマンドを設定の画面で登録できる．動作は アプリを開く・Web ページを開く(http・https)・ファイルを開く・ショートカットを実行(macOS だけ)
- コマンドは変換の一覧と分岐図(読み全体で 1 文節のとき)の 2 番目に「▶ 名前」で並ぶだけで，第 1 候補(ライブ変換で見える文字)にはしない．Enter で第 1 候補を確定しても動かない．利用者がその候補を選んで確定したときだけ動き，文字は入れない
- 安全のための決まり: 行き先は種類ごとの形だけを受け付け，シェルを通さず，打った文字や候補を引数に差し込まない．macOS は入力メソッドのプロセスで Launch Services に頼み，Windows はエンジンのプロセスで ShellExecuteW を使う(入力先のアプリに読み込まれた DLL では動かさない)．コマンドは同期せず(`SyncGroup.isSyncable`)，設定の読み込みでも置き換えない．Windows では設定の画面の実行ファイルからの接続でだけ書き換えを受ける(サンドボックスのアプリも DLL を通してエンジンにつなげるため)
- 変換マクロ: 変換中に連想変換のキー(R-18)で，選んでいる語を整えた形(「」で囲む・ルビ・Markdown など．`ConversionMacro`)を「整形」のまとまりに出す．形は設定で足せ，形ごとにオン・オフできる．動的な語(R-21)と同じ書き方(日時・乱数・変換)をすべて使える
- 初めから入れる形は 20 個(括弧・読みを添える形・小説投稿サイト・pixiv・HTML・LaTeX のルビ・傍点・ローマ字・Markdown・ハッシュタグ・Wikipedia へのリンク)．あとから足した形はオフで入れ，前の版で保存した一覧にもオフのまま足す(`MacroPresetUpgrade`)
- 語が読みと同じ(かなの語)ときは，語と読みを並べる形(ルビなど)を出さない(設定で切れる)
- 設定の画面で，試す語と読みに形を当てた結果を見られる．形の欄に書いている途中なら，その形だけを当てる(`ConversionMacroPreview`．Windows はエンジンに `previewMacros` で頼む)．使える書き方の一覧を画面に出す
- どれも既定ではオフ．初期設定の「試験的な機能」で紹介する
- 受け入れ条件: 「くろーど」に Claude を開くコマンドを登録すると，ライブ変換の表示と Enter では「クロード」を確定し，一覧で「▶ Claude を開く」を選んで確定したときだけ Claude が開く

## R-23 LaTeX のコマンドの候補

- 数式を書くときのため，ギリシャ文字や記号の読み(「らむだ」「せきぶん」)を変換すると，LaTeX のコマンド(「\lambda」「\Lambda」「\int」)を候補に出す．表は `LatexCommands` に置く．ふだんの文でよく使う語(「かける」「いじょう」)の読みは入れない
- 第 1 候補(ライブ変換で見える文字)は変えず，記号と同じ位置に差し込む
- 設定: 「LaTeX のコマンドに変換」．既定はオフ
- 受け入れ条件: オンにすると「らむだ」の候補に「\lambda」と「\Lambda」が出て，第 1 候補は変わらない．オフ(既定)では出ない

## R-24 英語の語の辞書

- ローマ字入力で英語の語を小文字で打つと，ローマ字として読める並びはかなになる(「api」→ あぴ，「openai」→ おぺない)．書き方の決まった英語の語(API・OpenAI・GitHub)を辞書に持ち，その書き方で候補に出す(`EnglishTermDictionary`)
- 語は，打つ英字(語を小文字にしたもの)と，その英字を打ったときの読みの両方で引く．読みはユーザー辞書の英字の読みと同じ決まりでそろえる(`ReadingNormalization`)．かな入力では英字を打ったときの読みでは引かない
- 読み全体が辞書の語になるときの並び(`SupplementedConverter`)
  - 英字の残る読み(「ぎてゅb」「あws」)は英語として打ったものなので，英語の語を第 1 候補にする
  - かなになり切った読みは，読み全体が漢字を含む辞書の 1 語(「そら」→ 空，「あい」→ 愛)なら日本語を先にして英語の語を 2 番目に，そうでなければ英語の語を第 1 候補にする．設定の「常に日本語にする単語」「常に英語にする単語」に入れた語はそれに従う
  - 打ったままの候補(あぴ・アピ)は消さない．ユーザー辞書と取り込んだ辞書の語(他の IME から取り込んだものを含む)より前には出さない．カタカナを先に出す並べ替えのあとに並べる
- 英単語として英字のまま確定させた語(「githubを使う」)は，辞書の書き方にした候補(「GitHubを使う」)を先に出す．大文字を含めて打った語は打ったとおりにする
- 英単語の補正(R-02)でも辞書の語を英単語とみなし，補正した語を辞書の書き方にする(`EnglishTermLexicon`)．スペルチェッカーが知らない語(「claude」→ Claude)や，文の中の語(「chatgptwotukau」→ ChatGPTを使う)も英語にできる
- 同梱の辞書は `data/english/english-terms.txt`(1 行に 1 語)．利用者は設定で語を足せ，足した語は同梱の語より先に出す．足した語は同じ形のファイルに書き出し・読み込みできる(`RuleList.englishTerms`)
- 設定: 「英語の語の辞書を使う」．既定はオン
- 受け入れ条件: 「openai」と打つと OpenAI を見せ，一覧にはオペ内・オペないも並ぶ．「sora」の第 1 候補は空のままで，Sora が 2 番目に出る．オフにすると出ない

## R-25 かな漢字変換の質の指標

変換の質は，次の指標で測る．変換・補正・区切りに触れる変更では，変更の前と後でこれらを測って PR に書き，どれも下げない．

- 文の変換(`make evaluate`．`hajime-playground --evaluate`)．評価用の文は次の 4 つ(AJIMEE-Bench と Tatoeba は `make fetch-evaluation` で取得する)
  - `core/Evaluation/conversion-basic.tsv`: 利用者から報告された例と，同音異義語を文脈で選ぶ例
  - `core/Evaluation/conversion-everyday.tsv`: ふだん打つ文(同音の動詞・熟語を文脈で選ぶ文，仕事と IT の文，日常の文)
  - AJIMEE-Bench: Wikipedia の文 200 文(文脈付きを含む)
  - Tatoeba: 人が付けたふりがなのある日本語の文から，文の番号で選んだ約 2,000 文(会話や日常の文が多い)
  - 第 1 候補の正解率(Accuracy@1)．文全体の第 1 候補が期待する文のどれかと同じ割合
  - 上位 10 候補の正解率．文全体の候補の上位 10 個に期待する文が入っている割合
  - MinCER．第 1 候補と期待する文との文字誤り率のうち最も小さいものの平均
- 期待する文に着くまでの操作(`make evaluate-operations`．`hajime-playground --evaluate-operations`)．読みを打って Space で変換したあと，アプリと同じ InputSession に ↓(候補)・← →(文節)・⇧← ⇧→(文節の長さ)を押し，期待する文になるまで押した数を数える．候補の出し方(分岐図・文節ごとの一覧・一覧)ごとに測る
  - 第 1 候補で正解(押す数が 0)の割合
  - 3 操作以内で着いた割合
  - 着いた割合(1 文で 60 回まで押す．1 つの文節で ↓ は 30 回，長さは前後 3 文字まで変えて探す)
  - 操作の平均．着かなかった文は 60 回と数える
- 打っている途中の表示(`hajime-playground --evaluate-live`)．確定する文と食い違う漢字やカタカナを見せた途中の表示の数(R-01)
- 打ち間違いの補正(`hajime-playground --evaluate-typo`)．直した・示した・誤って直した数(R-02)
- 本物の Zenzai のテスト(`make test-zenzai`)は，conversion-basic と conversion-everyday の第 1 候補の正解の数が下限を下回らないことを確かめる(ConversionAccuracyTests)．正解率を上げたら下限も上げる
- リリースの PR(タイトルが `chore(release)`)では，前のリリースのタグと PR の版を同じ CI の中で両方作り，文の変換の指標と起動の時間を比べて PR にコメントする(`.github/workflows/metrics.yml`．手元では `make release-metrics`)
- 1 キーの処理の時間(`core/Tests/HajimeEngineTests/LatencyProbeTests.swift`)(R-01)
- 受け入れ条件: 上の指標をすべて測れて，変更の前と後の数を PR に書ける

## R-26 絵文字と記号のパレット

- 絵文字・記号・顔文字を一覧から選んで入れる窓(パレット)．「絵文字のパレット」(既定は ⌃⌥E)・「記号のパレット」(既定は ⌃⌥K)・「顔文字のパレット」(既定は ⌃⌥F)のキーか，入力メニューの「絵文字と記号」で開き，⌃Tab で種類を切り替える．窓は入力先のアプリからフォーカスを奪わず，開いているあいだのキーは IME が受ける
- 顔文字は横に長いので，四角いマスをつなげた広いマスに並べる(窓の大きさは種類で変えない)．ピン留め・よく使う文字・探した結果には，今の種類とマスの形が同じ種類だけを出す(顔文字と，絵文字・記号を混ぜない)
- 文字のキーで探す．ローマ字はかなにして，読み(ひらがな)・日本語と英語の名前・キーワード・ショートコード(「:bow:」)を，打ったままの英数字とかなの両方で探す．あいまいにも当てるが，打ったとおりの当たり(同じ・頭から)を先に出す(`PaletteSearch`)
- マス目の並びは表の順(Unicode の絵文字の順と，記号のまとまり)で変えない．ピン留めとよく使う文字をその上に写しとして出し，よく使う文字は開いたときだけ作り直す(`PaletteUsage`)．同じ語で何度も選んだ文字は，その語で探したときに先頭に出す
- ローマ字入力では，パレットを開かずに読みの先頭から「:bow:」と打って閉じると，読みに替えてその絵文字を確定する．途中で文字のキー以外を押したら絵文字にしない(打ったキーと読みが対応しなくなるため)
- 絵文字は既定の肌の色と，絵文字ごとに選んだ肌の色で出して入れる．OS が描けない新しい絵文字は出さない
- 見た目はテーマ(カスタムテーマを含む)に合わせ，列数・行数・マスの大きさ・文字の説明・よく使う文字の行数を設定で変えられる
- 動きを付ける．開くと少し下から浮かび上がり，選択の枠と種類・まとまりの印は前の位置から滑り，種類を切り替えたときとまとまりへ飛んだときは中身を送り，肌の色の帯は浮かび上がり，ピン留めのピンは弾む．何が動いたかは core が決めて内容に添え(`PalettePanel.Motion`)，両 OS が同じ長さ(`motion.palette`)で動かす．動いている部品の範囲だけを動いているあいだだけ描き直す．OS の「視差効果を減らす」(macOS)・「アニメーション効果」(Windows)がオフを求めていれば動かさない
- 文字の説明は，見本の右の列に，見出しの日本語の名前(絵文字は CLDR の短い名前で，同じベースラインに「CLDR」と添える)と「項目名 → 値」の表を置く．項目は Unicode(1 つの符号位置の文字の UCD の名前．国旗・ZWJ・キーキャップなどの並びは項目名を「英語」にして CLDR の英語の短い名前)・読み・ショートコード・コードポイント．値はどの行も同じ x から書き出し，項目名と値はベースラインで合わせる．名前の読みは 1 度だけ出し，顔文字にはコードポイントを出さない．ショートコードとコードポイントは途中で切らない．Unicode の名前は 2 行までで，残りは読み上げで伝える．Unicode の名前・読み・ショートコード・コードポイントは，それぞれ出すかを設定で選べる(既定はすべて出す)．説明の欄の高さは，その種類で設定により出る行の分だけにし(顔文字は見出しと読み，記号はショートコードの行を除く)，選んでいる文字では変えない．窓の大きさは種類で変えず，説明の欄が低い種類はマス目の行を増やす(`PalettePanel.Preview`・`PalettePreviewLayout`・`PaletteWindowLayout`)
- 表は `data/palette/palette.tsv`(`tools/palette/update.sh` が Unicode・CLDR・azooKey の絵文字の辞書・iamcal/emoji-data・Mozc の顔文字の表から作る)．使った文字は端末の中にだけ保存し，同期しない．通信しない
- 受け入れ条件: ⌃⌥E で開き，「ojigi」と打って Enter で 🙇 が入る．「:bow:」と打つとそのまま 🙇 が入る(パレットを開かずに打っても入る)．記号のパレットで「やじるし」と打つと矢印が出る．顔文字のパレットで「shobo-n」(しょぼーん)と打つと (´・ω・｀) が先頭に出て，絵文字のパレットで探しても顔文字は出ない．よく使う文字の行は開いているあいだ並びが変わらない．パレットを使わない設定ではキーがアプリに渡る

## R-27 数字の書き方

- 読みが半角か全角の数字だけのとき，丸数字(⓪〜㊿，❶〜⓴)・括弧付き(⑴〜⒇)・ピリオド付き(⒈〜⒛)・漢数字(位取りの二〇二六，位付きの二千二十六，大字の弐千弐拾六)・ローマ数字(Ⅰ〜Ⅻ，ⅩⅢ など)を候補に出す(`NumberForms`)．書き方ごとに書ける範囲の外の数では，その書き方を出さない
- 0 で始まる 2 桁以上の数(電話番号の一部など)・小数・符号の付いた数は書き換えない
- 第 1 候補(ライブ変換で見える文字)は変えず，記号と同じ位置に差し込む．エンジンが出した書き方(「1」の ①)は重ねない．分岐図の文節の候補にも出す
- 設定: 「数字を丸数字などに変換」(既定はオン)と，書き方ごとのオン・オフ(丸数字・括弧付きとピリオド付きの数字・漢数字・ローマ数字．既定はすべてオン)
- 受け入れ条件: 「21」と打つと第 1 候補は 21 のままで，一覧に ㉑ が出る．「01」「1.5」では出ない

## R-28 数字と英字に続く記号

- 数字のあとの「.」「,」は句読点にせず，ピリオドとカンマにする(「3.14」「1,000」)．幅は直前の数字に合わせる(全角の数字なら「．」「，」)．句読点ではないので，「句読点で確定」でも確定しない
- 英数字(全角を含む)のあとの「-」は長音にせず，ハイフンにする(「A-1」「3-4」)．読みの先頭の「-」は，続けて数字を打ったときにハイフンにする(「-3」)．続く文字が決まるまでは長音にしておき，「->」は「→」，「--」は「ーー」のまま．かなのあとの「-」は長音
- 設定: 「数字のあとの句読点をピリオドとカンマに」「英数字のあとの長音をハイフンに」．既定はどちらもオン
- 受け入れ条件: 「3.14」「1,000」「-3」「A-1」がそのまま読みに入り，「らー」は「らー」のまま．設定をオフにすると「3。14」「ー3」になる
