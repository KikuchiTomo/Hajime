# デザインシステム

s90.tokyo IME の既定の見た目は，今の macOS になじむすりガラスの候補ウィンドウ(glass)です．文を幹として候補を曲線の枝で伸ばす分岐図(ADR 0007)を，角丸の選択・番号の丸・キーキャップ風の案内で描きます．
s90.tokyo のブランドの題材である漢字Talk 7 の時代の Macintosh とシティポップの東京は，選べる外観(platinum・desk)として残しています．

値の置き場所は `design/tokens/tokens.json` だけです．この文書の数値はそこからの抜粋で，食い違ったときは tokens.json が正しいものとします．

## 方針

1. **入力の邪魔をしない**．候補ウィンドウは読むための道具で，装飾は枝・選択・案内の形に使う．動きは利用者の操作に応えるときだけ付ける
2. **形で意味を見せる**．どの候補がどの文節から出ているかを枝の線で，どれを選んでいるかを角丸の地とアクセント色の枝で見せる
3. **文字は今の書体で読む**．文字は OS の書体だけを使う(同梱のフォントは無い)．テーマごとに系統を変える(システム・明朝・等幅・丸ゴシック)
4. **色の意味を固定する**．選択・補正・予測にはそれぞれ 1 色を割り当て，テーマが変わっても役割は変えない．glass の選択は OS のアクセントカラーに従う
5. **レトロな表現は描画で出す**．platinum の立体の縁は画像を貼らず，1 ドットの線をデバイスのピクセルにそろえて描く

## テーマ

| ID | 名前 | 題材 | 向いている場面 |
|---|---|---|---|
| `automatic`(glass) | 標準 | すりガラスの地，角丸，曲線の枝．色は OS の意味の色とアクセントカラー | 既定．ライトとダークの両方 |
| `platinum` | プラチナ | 漢字Talk 7.5 のプラチナ外観．灰色の面と立体の縁 | レトロな見た目が好きな人 |
| `desk` | 夜のデスク | s90.tokyo のデスクトップの紫と，カセットデッキの蛍光表示管の琥珀色 | 同上(暗い面) |
| `washi` | 和紙 | 生成りの紙に墨の文字，選択は朱．書体は明朝 | 文章を書くとき |
| `nordic` | 北欧 | 淡い灰の地に落ち着いた青 | 明るく静かな見た目が好きな人 |
| `neon` | ネオン | 夜の東京の看板．濃紺の地に桃色と水色．書体は丸ゴシック | 暗い画面 |
| `terminal` | 端末 | 黒い画面に緑の文字．書体は等幅 | ターミナルで書く人 |
| `contrast` | 高コントラスト | 黒い地に白い文字，選択は黄．常に「コントラストを上げる」の扱い | 見分けやすさを最優先にする人 |

和紙・北欧・ネオン・端末・高コントラストは，glass と同じ角丸と曲線の枝で描き，地を色で塗る．色は `tokens.json` の `theme`，コントラストは `check_contrast.py` で検査する．
足元の案内のキー(↓ ↑ ← → ⇧ ⌃ ⌥ ⌘ Tab Space)は，すべてのテーマで SF Symbols のアイコンをキーキャップの札に入れて描く．札の形は，角丸のテーマは角丸，platinum は立体の縁，desk は文字の色の縁取り．見本は `design/mockups/*-<テーマ>.png`

テーマの設定が「標準」(値は `automatic`)のときは，ライトでもダークでも glass を使います．以前の設定のファイルにある `native` も glass として読みます．

glass の色は OS の意味の色なので，`tools/tokens/check_contrast.py` の検査の対象外です．代わりに，ライト・ダーク・「コントラストを上げる」の 3 つで見本の画像(`design/mockups/`)を作り，目で確かめます．

### glass の色

OS の意味の色を使い，ライト・ダーク・アクセントカラーに OS が合わせます(`apps/macos/S90IME/UI/Theme.swift`)．

| 役割 | 色 |
|---|---|
| 地 | `NSVisualEffectView` の `.popover`(後ろをぼかす) |
| 縁 | `separatorColor` |
| 文字 / 弱い文字 | `labelColor` / `secondaryLabelColor` |
| 選択の地 / 文字 | `controlAccentColor` / `alternateSelectedControlTextColor` |
| 注目している文節の地 | アクセントカラーの 16% |
| 枝と区切りの線 | `tertiaryLabelColor` |
| 番号の丸・キーキャップの地 | `quaternaryLabelColor` |
| 補正の印 | `systemPink` |

### platinum と desk の色(抜粋)


| 役割 | platinum | desk |
|---|---|---|
| 面 `surface` | #DDDDDD | #220044 |
| 光の縁 `bevel-light` | #FFFFFF | #442277 |
| 影の縁 `bevel-shadow` | #999999 | #110022 |
| 外枠 `frame` | #000000 | #000000 |
| 文字 `text` | #000000 | #FFCC66 |
| 弱い文字 `text-muted` | #555555 | #9977BB |
| 選択の地 `selection` | #336699 | #FF3399 |
| 選択の文字 `selection-text` | #FFFFFF | #220044 |
| 補正の印 `correction` | #CC3366 | #33FFCC |
| 予測の印 `prediction` | #666666 | #9977BB |

desk の選択は，ネオンの桃色の地に紫の文字です．白い文字ではコントラストが 3.4:1 で足りないため，地の側の紫を文字に使っています．

文字と地のコントラストは WCAG 2.2 の AA(文字は 4.5:1，下線などの印は 3:1)以上にします．`tools/tokens/check_contrast.py` が `tokens.json` の `$extensions.s90.contrast` に書いた組み合わせを検査し，満たさないものがあれば止まります．

## 候補ウィンドウ

見本は `design/mockups/list-*.png` と `design/mockups/correction-*.png`(デバッグビルドの `--render-snapshots` で作る．glass は `-glass-light`・`-glass-dark`)．
図は platinum の形です．glass では選択を角丸の地にし，番号を小さな丸に入れ，足元の案内をキーキャップ風の札にします．

```
┌──────────────────────────────────────┐ ← 外枠 1 ドット(frame)
│ そのまま  カタカナ  ｶﾀｶﾅ  全角英数  半角英数 │ ← 文字種の行(R-03)．上キーで移る
├──────────────────────────────────────┤
│ 1  変換                              │
│ 2  返還                              │ ← 選択中は selection の地に白字
│ 3  偏官                              │
│ 4  へんかん                          │
├──────────────────────────────────────┤
│ 2 / 12                         ↑ 文字種 │ ← 足元．位置とキーの案内
└──────────────────────────────────────┘
```

- 縦に並べる．横に並べる設定も用意する(ライブ変換で予測だけを出すときは横が既定)
- 番号は 1〜9．番号のキーで直接選べる
- 文字種の行は，候補一覧の先頭で上キーを押したときだけ強調する．ふだんは弱い文字で見せておき，存在に気付けるようにする
- 足元は 1 行．操作の案内は 2 つまでに絞る

寸法(1 ドット = 1pt．Retina では 2 デバイスピクセル)．glass は `size.glass`(角丸 12，余白 10，行の高さ 28，番号の丸 17，選択の角丸 7，キーキャップの高さ 17)

| 項目(platinum・desk) | 値 |
|---|---|
| 行の高さ | 22 |
| 候補の文字の大きさ | 15(設定で 12〜24) |
| 番号の幅 | 18 |
| 左右の余白 | 8 |
| 外枠 | 1 |
| 立体の縁 | 1(光の縁が左と上，影の縁が右と下) |
| 影 | なし(platinum)．desk は 0,2 のぼかしなしの影 1 段 |

## 分岐図

Space で変換すると，文を幹とした分岐図を出します(ADR 0007)．

```
                ╭ ↑ ﾅｶﾉﾃﾞｽ
                ├ ↑ ナカノデス        ← 上の枝: 文字種
                ├ ↑ なかのです
私の  名前は  (中野です)              ← 幹．注目している文節はアクセントカラーの薄い地
      ‾‾‾‾‾   ┊‥‥‥‥‥                 ← 選び直した文節は実線，確信の低い文節は点線
              ├ ① 中のです            ← 下の枝: 変換の候補(5 件ずつ)
              ╰ ② 中野です            ← 選んでいる枝はアクセントカラーの線と角丸の地
[↓] 候補 [↑] 文字種 [←→] 文節 [Tab] 次の文節 [⇧←→] 文節の長さ     1–5 / 8
```

- glass の枝は，幹の文節の下(上)の 1 点から候補ごとに曲線(3 次ベジェ)で出す．線は `tertiaryLabelColor` の 1.5pt，選んでいる枝だけアクセントカラーの 2pt で最後に重ねる
- glass の幹は文節の間を空けるだけで線を引かない．文として読めるようにするため．文字は候補より 1 段太い(medium)
- platinum と desk は，幹の文節をつなぐ線と枝を 1 ドットの直線で描く．選んでいる枝の横線だけ selection の色で 2 ドット
- 下線は線の種類で意味を分ける．確信の低い文節は点線(補正の色)，選び直した文節は実線．色だけに頼らない
- 注目していない確信の低い文節の下には，次の候補を 1 つだけ弱い文字の色で添える．注目している文節の枝と重なる位置では描かない
- 幹の文節の位置は幹の文字の幅だけで決め，注目を移しても動かさない
- 足元の案内は普通の IME の言葉で書く(候補・文字種・文節・次の文節・文節の長さ)．glass はキーをキーキャップ風の札に入れる
- 寸法は `size.branch`(platinum・desk)と `size.glass`
- 見本は `design/mockups/branch-*.png`

## 出し始めの濃さ

候補ウィンドウを出した瞬間は，第 1 候補と選んでいる候補だけを濃く描き，残りを 250ms(`motion.candidate-rest.fade-in`)かけて濃くします．位置は動かしません．予測が当たっているときに残りを読まずに済むようにするためです(ephemeral adaptation)．「視差効果を減らす」が有効なら最初から濃く出します．

## 補正の表示(R-02)

```
入力中の文字:  python      ← 補正した部分に correction 色の点線の下線
候補:
  1  python
  2  pyてょn   入力のまま  ← 打ったままの文字列．Space で戻る
```

- 補正したことは下線の色と形だけで伝え，ポップアップは出さない．打っている手を止めないため
- 補正の直後の Space で元に戻ったときは，下線を消す

## モードの表示

入力方式を切り替えたとき，カーソルの近くに小さな札を出します．

| 方式 | 札 |
|---|---|
| ローマ字 | あ |
| かな | かな |
| EN | A |
| EN(日本語の候補あり) | A+あ |

- glass は角丸の正方形(34pt)にすりガラスの地，字はシステムの書体の太字．platinum と desk は立体の縁の札
- 表示は 0.8 秒．フェードは 120ms．「視差効果を減らす」が有効なら動かさず，出して消すだけにする
- プロファイルが自動で切り替わったとき(ターミナルに移ったときなど)は札の右にプロファイル名を添える

## 書体

| 用途 | macOS | Windows |
|---|---|---|
| 候補・幹の文字(glass) | システムの書体(SF．日本語はヒラギノ角ゴシック)．幹は medium | Yu Gothic UI |
| 番号・案内・札(glass) | システムの書体．数字は等幅の semibold | Segoe UI |
| platinum・desk・北欧・高コントラスト | システムの書体(高コントラストは 1 段太く) | Yu Gothic UI |
| 和紙 | ヒラギノ明朝(W3．幹と番号は W6) | Yu Mincho |
| 端末 | システムの等幅の書体(日本語はヒラギノ角ゴシック) | BIZ UDゴシック |
| ネオン | システムの丸ゴシック(SF Rounded) | Yu Gothic UI |

購入したフォント(s90.tokyo のサイトで使っている Chicago FLF など)は，再配布の条件があるため IME には同梱しません．

## 動き

| 動き | 長さ | 曲線 |
|---|---|---|
| 候補ウィンドウを出す | 0(すぐ出す) | なし |
| 選択の移動 | 0 | なし |
| モードの札のフェード | 120ms | ease-out |
| 補正の下線が出る | 80ms | linear |

候補の表示と選択の移動に動きを付けないのは，速く打つ人ほど待たされるからです．

## アクセシビリティ

- VoiceOver・ナレーターで候補と選択位置を読み上げる
- 「コントラストを上げる」が有効なときは，platinum と desk は立体の縁を外枠と同じ色にし，glass は線・弱い文字・番号の丸を 1 段濃い色にする．「透明度を下げる」が有効なときは，すりガラスの地を OS が不透明にする
- 文字の大きさは OS の設定と別に IME の設定で変えられるようにする

## 入力メニューのアイコン

メニューバーの入力ソースのアイコンはテンプレート画像(黒とアルファ)で，色は OS がメニューバーのライト・ダークに合わせて付けます．

- 本番は角丸の面を塗り，字(「あ」「A」)を抜く．右下の角だけ丸めず，分岐図の幹から枝が出る角に見立てる
- 開発版は面を塗らずに 1 ドットの枠だけにし，字を塗る．本番と並べたときに見分けるため
- 枠はピクセルにそろえ(16pt の中の 14×12)，1x(16px)と 2x(32px)を 1 つの tiff に入れる
- 作り方: `swift tools/icons/make_input_icons.swift apps/macos/S90IME/Resources design/mockups`．見本(ライトとダーク，8 倍の拡大と実寸)は `design/mockups/input-icons.png`
