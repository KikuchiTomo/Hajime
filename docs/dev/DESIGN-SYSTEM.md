# デザインシステム

s90.tokyo は，漢字Talk 7 の時代の Macintosh とシティポップの東京を題材にしたブランドです．
漢字Talk 7.1 には日本語入力の「ことえり」が付属していました．s90.tokyo IME の見た目は，その時代の入力メソッドの候補ウィンドウを出発点にし，今の高解像度の画面とダークモードで読みやすく作り直したものです．

値の置き場所は `design/tokens/tokens.json` だけです．この文書の数値はそこからの抜粋で，食い違ったときは tokens.json が正しいものとします．

## 方針

1. **入力の邪魔をしない**．候補ウィンドウは読むための道具で，装飾は縁取りと選択の表示だけにする．動きは利用者の操作に応えるときだけ付ける
2. **レトロな表現は描画で出す**．プラチナ外観の立体の縁(光の縁と影の縁)は画像を貼らず，1 ドットの線をデバイスのピクセルにそろえて描く．s90.tokyo のサイトと同じ考え方
3. **文字は今の書体で読む**．候補の文字は OS の日本語書体(macOS はヒラギノ角ゴシック，Windows は Yu Gothic UI)．ブランドの書体は番号と種類の行のラベルにだけ使う
4. **色の意味を固定する**．選択・補正・予測にはそれぞれ 1 色を割り当て，テーマが変わっても役割は変えない

## テーマ

| ID | 名前 | 題材 | 向いている場面 |
|---|---|---|---|
| `platinum` | プラチナ | 漢字Talk 7.5 のプラチナ外観．灰色の面と立体の縁 | 既定．ライトモード |
| `desk` | 夜のデスク | s90.tokyo のデスクトップの紫と，カセットデッキの蛍光表示管の琥珀色 | ダークモード |
| `native` | システム | OS の標準の色と角丸．装飾なし | ほかのアプリに見た目をそろえたい人 |

外観の設定が「自動」のときは，ライトモードで `platinum`，ダークモードで `desk` を使います．

### 色(抜粋)

| 役割 | platinum | desk |
|---|---|---|
| 面 `surface` | #DDDDDD | #220044 |
| 光の縁 `bevel-light` | #FFFFFF | #442277 |
| 影の縁 `bevel-shadow` | #999999 | #110022 |
| 外枠 `frame` | #000000 | #000000 |
| 文字 `text` | #000000 | #FFCC66 |
| 弱い文字 `text-muted` | #555555 | #9977BB |
| 選択の地 `selection` | #336699 | #FF3399 |
| 選択の文字 `selection-text` | #FFFFFF | #220044 |
| 補正の印 `correction` | #CC3366 | #33FFCC |
| 予測の印 `prediction` | #666666 | #9977BB |

desk の選択は，ネオンの桃色の地に紫の文字です．白い文字ではコントラストが 3.4:1 で足りないため，地の側の紫を文字に使っています．

文字と地のコントラストは WCAG 2.2 の AA(文字は 4.5:1，下線などの印は 3:1)以上にします．`tools/tokens/check_contrast.py` が `tokens.json` の `$extensions.s90.contrast` に書いた組み合わせを検査し，満たさないものがあれば止まります．

## 候補ウィンドウ

見本は `design/mockups/list-*.png` と `design/mockups/correction-*.png`(デバッグビルドの `--render-snapshots` で作る)．

```
┌──────────────────────────────────────┐ ← 外枠 1 ドット(frame)
│ そのまま  カタカナ  ｶﾀｶﾅ  全角英数  半角英数 │ ← 種類の行(R-03)．上キーで移る
├──────────────────────────────────────┤
│ 1  変換                              │
│ 2  返還                              │ ← 選択中は selection の地に白字
│ 3  偏官                              │
│ 4  へんかん                          │
├──────────────────────────────────────┤
│ 2 / 12                 ↑ 種類  ⇥ 予測 │ ← 足元．位置とキーの案内
└──────────────────────────────────────┘
```

- 縦に並べる．横に並べる設定も用意する(ライブ変換で予測だけを出すときは横が既定)
- 番号は 1〜9．番号のキーで直接選べる
- 種類の行は，候補一覧の先頭で上キーを押したときだけ強調する．ふだんは弱い文字で見せておき，存在に気付けるようにする
- 足元は 1 行．操作の案内は 2 つまでに絞る

寸法(1 ドット = 1pt．Retina では 2 デバイスピクセル)

| 項目 | 値 |
|---|---|
| 行の高さ | 22 |
| 候補の文字の大きさ | 15(設定で 12〜24) |
| 番号の幅 | 18 |
| 左右の余白 | 8 |
| 外枠 | 1 |
| 立体の縁 | 1(光の縁が左と上，影の縁が右と下) |
| 影 | なし(platinum)．desk は 0,2 のぼかしなしの影 1 段 |

## 文節格子

文節が 2 つ以上ある読みを変換すると，一覧の代わりに文節格子を出します(ADR 0005)．

```
┌──────────────┬──────────────┐
│ 私の名前は   │ 中のです     │ ← 1 段目: ライブ変換と同じ文を文節で区切る．注目している文節は selection の地
├──────────────┼──────────────┤
│              │ 1 中のです   │ ← 注目している文節の候補．番号で選ぶ
│              │ 2 なかのです │
│              │ 3 中野です   │
├──────────────┴──────────────┤
│ ← → 文節　↑ ↓ 候補　⇧← → 区切り │
└─────────────────────────────┘
```

- 注目していない文節は，確信度が低いときだけ候補の列を text-muted の色で見せる．番号は付けない(選べるのは注目している列だけ)
- 候補の並びは列の中で固定し，注目を移しても動かさない
- 見本は `design/mockups/lattice-*.png`

## 出し始めの濃さ

候補ウィンドウを出した瞬間は，第 1 候補と選んでいる候補だけを濃く描き，残りを 250ms(`motion.candidate-rest.fade-in`)かけて濃くします．位置は動かしません．予測が当たっているときに残りを読まずに済むようにするためです(ephemeral adaptation)．「視差効果を減らす」が有効なら最初から濃く出します．

## 補正の表示(R-02)

```
入力中の文字:  python      ← 補正した部分に correction 色の点線の下線
候補:
  1  python
  2  pyてょn   入力のまま  ← 打ったままの文字列．Space で戻る
```

- 補正したことは下線の色と形だけで伝え，ポップアップは出さない．打っている手を止めないため
- 補正の直後の Space で元に戻ったときは，下線を消す

## モードの表示

入力方式を切り替えたとき，カーソルの近くに小さな札を出します．

| 方式 | 札 |
|---|---|
| ローマ字 | あ |
| かな | かな |
| EN | A |
| EN(日本語の候補あり) | A+あ |

- 表示は 0.8 秒．フェードは 120ms．「視差効果を減らす」が有効なら動かさず，出して消すだけにする
- プロファイルが自動で切り替わったとき(ターミナルに移ったときなど)は札の右にプロファイル名を添える

## 書体

| 用途 | macOS | Windows |
|---|---|---|
| 候補の文字 | ヒラギノ角ゴシック | Yu Gothic UI |
| 番号・種類の行・札 | BIZ UDゴシック(OFL．同梱) | 同左 |
| 設定アプリの見出し | BIZ UDゴシック | 同左 |

購入したフォント(s90.tokyo のサイトで使っている Chicago FLF など)は，再配布の条件があるため IME には同梱しません．

## 動き

| 動き | 長さ | 曲線 |
|---|---|---|
| 候補ウィンドウを出す | 0(すぐ出す) | なし |
| 選択の移動 | 0 | なし |
| モードの札のフェード | 120ms | ease-out |
| 補正の下線が出る | 80ms | linear |

候補の表示と選択の移動に動きを付けないのは，速く打つ人ほど待たされるからです．

## アクセシビリティ

- VoiceOver・ナレーターで候補と選択位置を読み上げる
- 「コントラストを上げる」が有効なときは，立体の縁を外枠と同じ色にする
- 文字の大きさは OS の設定と別に IME の設定で変えられるようにする
