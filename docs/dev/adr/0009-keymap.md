# 0009 キー操作は状態・キー・コマンドの表で決める

- 状態: 採用
- 日付: 2026-10-26
- 関係する要件: R-09，R-17

## 背景

版 2 までは，変換中の操作のキー(`KeyBindings`)と，日本語と英数を切り替えるキー(`ModeKeyAssignments`．英数・かな・半角/全角・変換・無変換に 4 つの値から選ぶ)を別々に持ち，Enter・Esc・Backspace・F6〜F10・Ctrl+J などは `InputSession` に書き込んでいた．利用者から，好きなキーや組み合わせに，すべての動作を好きなだけ割り当てたいと求められた．かなキーの無いキーボードで日本語と英数を切り替えるキーも決められなかった．

## 判断

- キー操作を「状態・キー・コマンド」の行の表(`Keymap`)で決める．行は好きなだけ足せる．`S90Domain/Settings` に置き，macOS 版と Windows 版で同じ表を使う
- 状態は 4 つと「いつでも」にする．他の IME のキー設定の状態とは次のように対応する

| s90 | 他の IME の状態 | 理由 |
|---|---|---|
| 英数 | 直接入力 | IME がオフ |
| 入力文字なし | 入力前，入力前の候補 | 何も組み立てていない．s90 は入力前の候補を出さない |
| 入力中 | 入力中，サジェスト表示中 | s90 はサジェストの窓を出さない(ライブ変換と「もしかして」は入力中の表示) |
| 変換中 | 変換中，予測変換中 | 分岐図と候補の一覧は同じ「変換中」．一覧は分岐図と出し方が違うだけなので分けない．s90 は予測変換をしない |
| いつでも | (無い) | 英数キー・Enter・F7 のように多くの状態で同じ働きのキーを 1 行で書けるようにする．コマンドが効く状態でだけ効く |

- 重なりの決まり: 同じ状態の同じキーは表の下の行を使う(新しく足した行が効く)．状態を選んだ行は いつでも の行より優先する．設定の画面で，使われない行と，修飾キーの無い文字のキーで文字を打てなくなる行に印を付け，入力中・変換中に確定と取り消しのキーが無ければ知らせる．表は利用者のもので，確定のキーを消すことも止めない(知らせるだけ)
- 表に無いキーは，文字なら読みに足し，ほかのキーは組み立て中なら何もせず(読みが入力先に混ざらないように)，組み立てていなければアプリに渡す．⌘ の組み合わせも表に書け，表に無いものはアプリのショートカットとして渡す
- 数字キーで候補を選ぶ動きは表に入れない．1〜9 の 9 行を足さずに済むよう，「番号キーで候補を選択」の設定に従う．分岐図で文節を数字で区切っているときの数字と Esc も，その操作の中だけの決まりとして表に入れない
- 英字入力では，読みを組み立てていないとき(英字を打っている途中と何も打っていないとき)は英語の入力と同じに動かし，表は入力モードと設定を開くなどのコマンドにだけ使う(Space・Shift+Space を英語の入力と同じにアプリに渡すため)
- 設定のファイルにはキーを「Ctrl Shift Space」のような文字列で書く．人が読めて直せるようにするため．この版が知らないコマンドの行は消さずに書き戻す
- 設定のファイルの形式の版を 3 に上げ，版 2 の `conversionKeys` と `modeKeys` を表に移し替える(`LegacyKeySettings`)．既定から変えていない項目は標準の表のままにし，変えた項目だけをその状態の行で置き換える．版 2 の切り替えのキーはほかの働きより先に効いたので，切り替えに割り当てたキーのほかの行は消す．古い版の Mac が同期のファイルに書いた値も，取り込むときに同じように移し替える
- 入れたコマンドと入れなかったものは次のとおり

| 入れた | 入れなかったもの | 入れない理由 |
|---|---|---|
| 日本語入力・英数入力・切り替え・入力方式の切り替え・取り消して英数入力に | カタカナ・全角英数・半角英数の入力モード | s90 の入力モードは OS の入力メニューの入力ソース(日本語と英数)と対応している．カタカナで打つときは字種の変換を使う |
| 空白(設定の幅・逆の幅・半角・全角) | | |
| 変換・学習を使わずに変換・左の文字を削除・ここで区切る・「もしかして」に直す | 読みの中のカーソル移動，右の文字の削除 | 読みの途中にカーソルを置く仕組みが無い．入れるならライブ変換の表示と打ち間違いの訂正の見直しが要る |
| 字種の変換 5 つ・かなの種類の切り替え | 表示だけを変える字種の変換 | 字種は候補として選ぶ形 1 つにした |
| 候補の前後・ページ・先頭・末尾 | 予測変換・サジェストの確定 | s90 は予測候補を出さない(docs/user/reference/settings.md の「入れない項目」) |
| 文節の前後・先頭・末尾・迷う文節・長さ・区切り | | |
| 確定・先頭の文節だけ確定・取り消し・読みに戻す | 確定の取り消し(確定した文字を消して変換に戻す)・再変換 | 入力先のアプリの文字を書き換える必要があり，アプリによって動きが違う．入力欄の文字を読む仕組みも要る |
| 候補を学習から削除・最後の学習を取り消し | | 最後の学習の取り消しは，入力した文字は消さず，最後に確定した語の学習だけを消す |
| 設定を開く・ライブ変換・手書き | 辞書ツール・単語登録の窓 | 設定の画面の辞書のページで行う．ページを指して開く操作は今は無い |

- ひな形は 標準・Windows 風・Mac 風・Emacs 風・Vim 風．Windows 風と Mac 風は，BSD 3-Clause で公開されているキー設定の表(出どころは THIRD_PARTY_NOTICES.md)の行を s90 の状態とコマンドに置き換え，s90 に無いコマンドの行を除いて作った

## 検討したほかの案

| 案 | 採らなかった理由 |
|---|---|
| コマンドごとにキーの一覧を持つ(版 2 の形)を広げる | 同じキーを状態ごとに違うコマンドにできない(Space が入力文字なしでは空白，入力中は変換，変換中は次の候補) |
| 同じ状態の同じキーは上の行を使う | 新しく足した行が効かず，利用者が直したつもりで直らない |
| Enter・Esc・Backspace を表の外で固定する | 好きなキーにすべての動作を割り当てたいという求めに合わない．確定・取り消しのキーが無いときは画面で知らせることで，操作できなくなるのを防ぐ |
| 候補の一覧を「変換中」と別の状態にする | 行が倍に増える．一覧は分岐図と出し方が違うだけで，同じキーで同じ操作をしたい |

## 結果

- 好きなキーと組み合わせに，すべての操作を割り当てられる．かなキーの無いキーボードでも切り替えのキーを決められる
- `InputSession` のキーの解釈は表を引いてコマンドを行う形になり，キーを書き込んだ分岐が減った
- 分岐図の足元の案内と，打ち間違いの案内(「Esc で戻す」「Tab で直す」)のキーは表から引く
- 古い版の Mac と同期すると，新しい版で変えた表は古い版には届かない(古い版は `keymap` を知らない)．古い版で変えたキーは新しい版に移し替えて取り込む
- 切り替えのキーは版 2 では「この Mac だけ」のまとまり(キー配列)だったが，表にまとめたので「キー設定」のまとまり(既定で同期する)に入る
