# 0002 入力の処理は OS に依存しない Swift のパッケージに置く

- 状態: 採用
- 日付: 2026-10-25
- 関係する要件: R-01〜R-07

## 背景

要件の多く(補正，種類の行，¥ キー，プロファイル，コマンド入力)は，キーの列に対する判断であり，OS ごとの違いは画面への反映のしかただけにある．
azooKey-Desktop では判断と macOS の API の呼び出しが 1 つのクラスに同居していて，Windows では使い回せない．

## 判断

- 判断は `core/`(Swift Package `S90Core`)に置き，OS ごとのアプリはキーの変換と `ClientAction` の反映だけを行う
- Swift を選ぶのは，変換エンジン(AzooKeyKanaKanjiConverter)が Swift で書かれていて，Windows でも Swift のツールチェーンで動くため

## 検討したほかの案

| 案 | 採らなかった理由 |
|---|---|
| core を Rust で書き，エンジンを FFI で呼ぶ | エンジンの型を Rust 側に写す層が増え，二重に保守することになる |
| OS ごとに判断を書く | 同じ要件を 2 回実装することになり，動きが食い違う |

## 結果

要件の受け入れ条件を，OS を起動せずに core のテストで確かめられる．
Windows では Swift の実行環境を配布物に含める必要がある．
