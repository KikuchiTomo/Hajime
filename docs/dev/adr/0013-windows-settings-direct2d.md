# 0013 Windows の設定の画面は Direct2D で描く

- 状態: 採用
- 日付: 2026-10-27
- 関係する要件: R-15(設定の同期)，R-17(キー設定の表)

## 背景

Windows の設定の画面(`s90-settings.exe`)は，Win32 の標準の部品(STATIC・BUTTON・COMBOBOX・LISTBOX・ListView・EDIT)を GDI で描いていた．使ってみると次の困りごとがあった．

- 暗い地に GDI の ClearType で描いた文字が色ずれして滲む．検索欄・入力欄・ドロップダウン・スクロールバーが古い見た目のままで，ダークの見た目も部品ごとに揃わない(時々文字の色が反転する)
- ページを開くたびに，すべての行の部品を子の窓として作り直していた．スクロールでは子の窓を全部置き直していて，描き直しが追いつかずに崩れた
- 窓を出す前にエンジンへの接続と設定の読み込みを済ませていたので，エンジンが動いていないと中身がなかなか出ず，読み込み中の表示も無かった
- 動き(ページの入り・トグル・ドロップダウン・なめらかなスクロール)を付けられない

利用者は「Windows 11 の設定アプリぐらいサクサク動く」ことを求めている．

## 判断

- 設定の画面は 1 枚の窓に Direct2D と DirectWrite で描く．部品は子の窓にせず，状態(`app/page.rs`)として持って描く(`app/paint.rs`)．候補ウィンドウ(`candidate-ui`)と同じ描き方で，新しい依存は足さない
- 文字は DirectWrite のグレースケールの滑らかさにする(Windows 11 の XAML と同じ)．英数字は Segoe UI Variable，日本語は Yu Gothic UI(書体の代わりの決まりで組み合わせる)
- 文字を打つ欄だけは標準の EDIT を枠なしで使い，枠は Direct2D で描く．IME・クリップボード・読み上げを自分で作り直さないため．EDIT はページをまたいで使い回す(作るのに 1 つ数ミリ秒かかる)
- ドロップダウンの開いた一覧は，前に出さない自前の窓(`WS_EX_NOACTIVATE`)に描く
- 動きは必要なときだけフレームを回す．描き終えたら `DwmFlush` で画面の合成に合わせ，止まっているときは描かない．OS の「アニメーション効果」を切っていれば動かさない
- 窓を先に出し，エンジンへの接続と設定の読み込みは別のスレッドで行う．そのあいだは読み込み中の輪を出す
- 自分で描いた部品は UI Automation の要素として出す(名前・役割・状態と，押す・切り替える・開く・選ぶの操作)．打つ欄は EDIT が自分で読ませる
- 部品の配置(`layout.rs`)・動き・スクロール・表の選び方・左の一覧の並び(`ui/`)は OS に依存しない層に置き，テストする
- 色・寸法・動きの長さは `design/tokens/tokens.json` の `settings-windows` に置く

窓の地は Windows 11 の Mica(`DWMSBT_MAINWINDOW`)にする．枠を窓の中まで広げ，地(ページとサイドバー)を透明で描いたところに Mica が見える．カードと部品は不透明のまま描く．
子の窓の EDIT は GDI で描くので，そのままでは透けてしまう．EDIT は自分の面を持つ窓(`WS_EX_LAYERED` の子の窓．不透明)にし，そのためにマニフェストに Windows 10/11 の宣言を入れる(`crates/settings/s90-settings.manifest`)．
自分の面を持つ窓は，描画を終えたあとに DC を借りて重ねた絵が画面に出ないので，案内の文字は `WM_PAINT` の中で既定の描き方(`WM_PRINTCLIENT`)と一緒に描く．
Mica を使えない Windows(22H2 より前)と高コントラストのときは，地を不透明で塗る．

## 検討したほかの案

| 案 | 採らなかった理由 |
|---|---|
| 今の Win32 の部品を磨く(自分で描く部分を増やす) | 動き・読み込み中の表示・なめらかなスクロールを出せない．部品ごとの子の窓が重さと崩れの元のまま |
| WinUI 3(Windows App SDK) | 見た目は最も近いが，ランタイムの同梱など大きな依存が増え，Rust から扱いにくい |
| 文字を打つ欄も自分で作る | IME の組み立て中の表示・候補の位置・クリップボード・読み上げを作り直すことになる |

## 結果

ページを開くのは子の窓を作らない分だけ速くなり，2 回目からは描くのに 1 ミリ秒もかからない(`--measure` で測る．数値は `docs/dev/WINDOWS.md`)．見た目は部品の形(`app/paint.rs`)とトークンで決まり，ライト・ダーク・高コントラストで揃う．

代わりに，標準の部品が持っていたキーボードの操作・フォーカスの移り方・読み上げは自分で持つ．部品を足すときは，描き方に加えて `page::Part` のフォーカスの順・押したときの頼み・読み上げの役割も足す．
