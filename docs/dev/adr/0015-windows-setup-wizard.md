# 0015 Windows 版にインストール後の再起動の案内と，実演つきの初期設定ウィザードを置く

- 状態: 採用
- 日付: 2026-10-28
- 関係する要件: R-01

## 背景

Windows 版を入れた直後は，文字入力のサービスの DLL が起動中のアプリに読み込まれず，入力がおかしく見える．
インストーラーは再起動が要ることを伝えていなかった．

また，はじめには英語と日本語の切り替え方・ライブ変換・分岐図・補正など，既定のままでは気づきにくい選択と機能が多い．
設定の画面の項目は多く，初めて使う人が何を決めればよいかわからない．利用者からは，最初に要点だけを実際の動きを見ながら選べるウィザードが欲しいと求められた．

## 判断

- インストーラーは入れ終えたら(上書きも)Windows Installer の `ScheduleReboot` で再起動を求める．標準の確認を使い，自前の画面は作らない
- 初期設定ウィザードは `hajime-settings.exe` の別の窓(`--setup`)にする．設定の画面と同じ描き方・色・寸法・読み上げを使い，値の読み書きはエンジンに頼む
- HKLM の `Run` に `hajime-settings.exe --setup-if-needed` を入れ，ログオンのたびに起動する．済んだかどうかは HKCU の `SetupCompleted` に書き，済んでいればすぐ終わる
- 済んだことはエンジンの設定のファイルに書かない．設定のファイルは同期と書き出しの対象で，別の PC に移しても，その PC ではウィザードを出したいため
- 各ページの実演は，台本(時間で進むコマの並び)を OS に依らない層で作り，候補の窓は候補ウィンドウの描き方で描く．選んだ値で台本を作り直すので，選ぶとすぐ実演に出る．止まっているコマのあいだは時計で待ち，CPU を使わない
- 英語と日本語の切り替え方は設定の 1 つの項目でなく，キー設定の表の行で表す．「変換・無変換」を選ぶと `idle` の `Muhenkan → directMode` と `direct` の `Henkan → japaneseMode` を表の最後に足す．状態を書いた行は「いつでも」の行に勝つので，ほかの行は変えない
- macOS 版は別に作る．両方がそろうまでリリースしない

## 検討したほかの案

| 案 | 採らなかった理由 |
|---|---|
| WiX の自前の画面で再起動を伝える | 標準の確認で足りる．画面を作ると文言と見た目を 2 か所で保つことになる |
| 済んだことを settings.json に書く | 同期・取り込みで別の PC に移り，その PC でウィザードが出なくなる |
| ウィザードを別の実行ファイルにする | 設定の画面と描き方・エンジンへの接続・読み上げが同じで，分けると重なる |
| 実演を動画や画像で見せる | 選んだ値を映せず，テーマ・明暗・DPI に合わせられない |

## 結果

- ウィザードの文言は `strings.rs` の `wizard`(Windows だけの文言)に置く．macOS 版を作るときに UIStrings へ移し，`check_strings.py` で比べる
- 寸法と動きの長さは `tokens.json` の `settings-windows` の `wizard-*`
- 「あとで」や窓を閉じたときは済んだことにしないので，完了するまでログオンのたびに出る
