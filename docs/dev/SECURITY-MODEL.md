# セキュリティモデル

入力メソッドは，パスワードやメッセージを含め，利用者が打つすべてのキーを受け取ります．
そのため s90.tokyo IME では「入力した内容を端末の外に出さない」「入力先のアプリを壊さない」の 2 つを，ほかの機能より優先します．

脆弱性の報告の窓口は `SECURITY.md` にあります．

## 守るもの

| 資産 | 例 | 置き場所 |
|---|---|---|
| 入力中の文字列 | 打っている途中の読み，確定した文字 | メモリの中だけ |
| 学習データ | 確定した語の履歴 | ユーザーのディレクトリ(下記) |
| ユーザー辞書 | 登録した語 | 同上 |
| 認証情報 | オプトインの外部機能の API キー | macOS はキーチェーン，Windows は資格情報マネージャー |

## 想定する脅威

1. 入力した内容が，ログ・クラッシュレポート・通信を通じて端末の外に出る
2. 同じ端末のほかのユーザーや，権限の低いプロセスが学習データやエンジンとの通信を読む
3. 細工したファイル(ローマ字表・ユーザー辞書のインポート・テーマ)で IME が落ちる，または任意のコードが動く
4. 依存ライブラリ・辞書・モデルのファイルが差し替えられる
5. IME の不具合で，入力先のアプリ(Windows では IME の DLL が読み込まれたすべてのプロセス)が落ちる

## 決まり

### 入力内容

- 入力した文字列・読み・候補をログに書かない．ログに出してよいのは件数・長さ・処理時間・状態の名前だけ
  - 調べるために中身が要るときは，デバッグビルドで，設定の「入力内容を記録する」を利用者が明示して有効にした場合に限る．出力先はローカルのファイルだけ
- パスワード欄では何もしない
  - macOS: Secure Input が有効なときは IME に入力が来ない．来た場合も変換せずに素通しする
  - Windows: 入力欄の InputScope が `IS_PASSWORD` などのときは変換も学習もしない
- 学習しないアプリの一覧を設定に持つ．既定でパスワード管理アプリとターミナルの `sudo` の入力(エコーが切られている入力欄)を含める
- クリップボードは，利用者が明示した操作(選択した文字の再変換など)のときにだけ読む

### 通信

- **既定では一切通信しない**．アップデートの確認も含め，通信する機能はすべてオプトインにする
- 通信する機能(いい感じ変換のような LLM を使う機能など)は，core から切り離した別のモジュールにし，送る内容を画面で確かめられるようにする
- 辞書やモデルを追加で取得するときは，リポジトリに書いた SHA-256 と一致しないファイルを読み込まない

### 保存

- 保存先
  - macOS: `~/Library/Application Support/tokyo.s90.ime/`
  - Windows: `%LOCALAPPDATA%\s90.tokyo\IME\`(ローミングしない)
- ファイルは本人だけが読み書きできる権限で作る(macOS は 0600，Windows は所有者だけの ACL)
- 学習データとユーザー辞書は，設定画面から消せて，書き出せるようにする

### 外から来るファイル

- 読み込む前に大きさの上限を確かめる(上限は `DefaultSettings.swift` に置く)
- パースは失敗を `throws` で返し，プロセスを落とさない
- テーマは値(色・寸法)だけのファイルにし，コードや任意のパスを含めない
- パーサにはファズテストを用意する(`core/Tests/Fuzz/`)

### Windows のプロセス間通信

- 名前付きパイプはユーザーごと・セッションごとの名前にし，ACL で本人の SID だけを許可する
- `PIPE_REJECT_REMOTE_CLIENTS` を付け，ネットワーク越しの接続を受けない
- メッセージには長さの上限を設け，超えたら接続を切る．形式は `protocol/` の定義だけを受け付ける
- 接続してきたプロセスの ID を確かめる(`GetNamedPipeClientProcessId`)

### 入力先のアプリを壊さない

- TSF の DLL は COM の境界で Rust の panic を受け止め，`E_FAIL` を返す
- DLL の中でブロックする処理をしない．エンジンからの応答には時間の上限を設け，超えたら読みのまま返す
- `unsafe` は `ffi` / `com` モジュールに閉じ込め，ブロックごとに安全である理由をコメントに書く
- macOS の候補ウィンドウはメインスレッドだけで触る

### 供給網

- 依存は revision・ロックファイルで固定する．Dependabot の更新は CI と人の確認を通してから入れる
- GitHub Actions のアクションはコミットの SHA で固定し，ワークフローの `permissions` は最小にする
- 配布物は署名する．macOS は Developer ID と公証，Windows は Authenticode
- azooKey の fork から取り込むときも，差分を読んでから入れる(`docs/dev/UPSTREAM.md`)
